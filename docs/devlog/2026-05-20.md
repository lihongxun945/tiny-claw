## 上下文压缩实现

实现了基于模型摘要的上下文压缩机制，防止长任务上下文溢出。

### 新增文件

- `src/compress.ts` — 压缩逻辑：优先压缩历史对话，回退压缩当前轮早期，失败兜底截断
- `src/estimate-tokens.ts` — Token 估算（CJK 1.5/字，ASCII 0.25/字），粗略判断是否接近上限

### 改动文件

- `src/types.ts` — Config 新增 `maxContextTokens`（默认 128000）和 `contextCompressionThreshold`（默认 0.7）
- `src/config.ts` — 加载新配置字段
- `src/client.ts` — 新增 `complete()` 非流式方法，用于压缩时调用模型摘要
- `src/history.ts` — 新增 `getTurnStartIndexInContext()` 和 `replaceWithCompressed()`，支持压缩集成
- `src/index.ts` — Agent Loop 中调用 `compressIfNeeded()`，超阈值时自动压缩
- `docs/architecture.md` — 更新进度、模块结构、配置字段、数据流、压缩设计决策

### 设计决策

- **压缩触发**：token 估算 > `maxContextTokens * contextCompressionThreshold` 时触发
- **压缩策略**：优先压缩 markTurnStart 之前的历史（摘要为一条消息），回退压缩当前轮早期（保留最后4条），失败兜底截断（保留最后2条）
- **非流式调用**：压缩用 `client.complete()`，max_tokens=1024，避免流式开销

## 搜索引擎重构：多 Provider 架构

原 DuckDuckGo HTML 爬取频繁触发反爬验证（anomaly/captcha），重构为支持三个搜索引擎。

### 改动文件

- `src/types.ts` — Config 新增 `searchProvider`、`searxngUrl`、`braveApiKey`
- `src/config.ts` — 加载新字段，默认 `searchProvider: "duckduckgo"`
- `src/tools/search.ts` — 重写：定义 `SearchProvider` 接口，实现 `SearXNGProvider`、`BraveProvider`、`DuckDuckGoProvider`
- `src/index.ts` — `createWebSearchTool(config)` 传入配置
- `config.example.json` — 新增搜索配置示例
- `docs/architecture.md` — 更新搜索引擎文档、配置字段

### 搜索引擎对比

| Provider | 说明 | 配置 |
|----------|------|------|
| duckduckgo（默认） | Instant Answer API，无需 key | 无 |
| searxng | 自建实例，完整搜索结果 | `searxngUrl` |
| brave | 官方 API，结果质量好 | `braveApiKey` |

### 搜索问题排查

1. **`fetch failed`** — 缺少 User-Agent 和超时控制，添加后修复
2. **DuckDuckGo Instant Answer 对中文查询无数据** — API 基于英文维基百科等数据源，中文覆盖极差
3. **模型传长查询导致无结果** — Instant Answer 需要短实体关键词（如 "iPhone 17"），但模型倾向传完整句子
4. **通过 system prompt 约束模型搜索行为** — 在 system prompt 中明确要求 "1-3个简短英文实体关键词" 并给出错误示例，实测有效
